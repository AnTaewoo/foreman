  수정하면 좋은 것

  1. "프로젝트 삭제" 버튼이 위험한 자리에 있습니다 (index.html:40)
  - 페이지에서 가장 파괴적인 동작인데 Goals 제목 바로 아래, Goal 입력창 위에
    상시 노출됩니다.
  - .secondary 회색이라 위험 동작으로 보이지도 않습니다.
  - 확인 창은 "삭제(보관)할까요?"라고 묻는데 버튼에는 "삭제"만 있고, 실제로는
    보관이라는 설명이 툴팁에만 있습니다.
  - → "프로젝트 보관"으로 이름을 바꾸고, 프로젝트 선택기 옆 ⋯ 메뉴나 페이지 하단
    "위험 구역"으로 옮기고, 빨간색 계열로 구분하는 편이 좋습니다.

  2. 안내 문구가 선택한 LLM과 맞지 않습니다 (index.html:28, demo.js:157)
  - "1~3분 뒤 Plan이 올라옵니다(로컬 LLM)"이 하드코딩돼 있습니다.
  - 지금은 ollama, openai, anthropic을 고를 수 있어서 openai를 골라도 "로컬 LLM,
    1~3분"이라고 나옵니다.
  - → goal.llm 값에 따라 문구를 바꾸거나, "로컬 LLM" 언급을 빼면 됩니다.

  3. 에러와 결과가 전부 토스트로만 나옵니다 (demo.js:17)
  - 6초 뒤 사라지고 다시 볼 수 없습니다.
  - 내용이 400: {"detail":...} 같은 원문 JSON입니다.
  - aria-live가 없어 스크린리더에는 읽히지 않습니다.
  - Goal 생성 실패(프로파일 probe 400 등)는 사용자가 읽고 조치해야 하는
    내용입니다.
  - → 폼 바로 아래에 지워지지 않는 인라인 에러를 두고, 토스트에는 닫기 버튼과
    role="status"를 붙입니다.

  4. 진행 중 상태가 보이지 않습니다
  - Approve, Reject, Goal 취소는 클릭해도 버튼이 비활성화되지 않아 두 번 누를 수
    있습니다 (demo.js:217-242).
  - Goal 생성은 probe 때문에 몇 초가 걸리는데 버튼이 흐려지는 것 외에는 표시가
    없습니다.
  - → "생성 중…", "승인 중…" 라벨로 바꾸고 그동안 disabled로 둡니다.

  5. Reject 입력창의 비중이 큽니다 (index.html:76-80)
  - Approve, Reject, 거절 사유 입력이 한 줄에 같은 무게로 놓여 있습니다.
  - 사유 입력은 Reject에만 쓰이는데 Approve 옆에 늘 보입니다.
  - → Reject를 누르면 사유 입력이 펼쳐지게 하고 확인 단계를 둡니다. 지금
    Reject는 confirm이 없습니다.

  6. 프로젝트를 바꾸면 페이지 전체가 새로고침됩니다 (demo.js:103-106)
  - 라이브에 프로젝트가 3개 이상(Foreman_test1~`Foreman_test3`) 있어서 프로젝트
    전환이 자주 일어납니다.
  - → 새로고침 없이 상태만 다시 읽게 합니다. 최소한 선택한 Goal은 URL(?goal=)에
    남겨 새로고침이나 공유 때 유지되게 합니다.

  7. 이벤트 로그가 Goal별로 걸러지지 않습니다 (demo.js:170-185)
  - Goal을 선택한 상세 패널 안에 있는데 내용은 프로젝트 전체 이벤트입니다.
  - 엔티티 ID는 끝 6자리만 보여서 어떤 Task의 이벤트인지 알기 어렵습니다.
  - task.failed의 테스트 출력은 세 줄을 |로 이어 붙이고 300자에서 자릅니다. 실패
    원인을 읽기에는 부족합니다.
  - → 기본은 현재 Goal만 보이게 하고 "전체 보기" 토글을 둡니다. 실패 이벤트는
    클릭하면 전체 출력이 펼쳐지게 합니다.

  8. Task 행이 클릭된다는 표시가 없습니다 (demo.js:166)
  - 행을 클릭하면 spec이 펼쳐지는데 커서, 화살표, hover 표시가 없어 기능을 찾기
    어렵습니다.
  - 행 안의 Issue/PR 링크를 눌러도 spec이 같이 토글됩니다.
  - → ▸ 아이콘과 cursor:pointer를 넣고, 링크 클릭은 stopPropagation 처리합니다.

  9. 상태 배지가 내부 enum 그대로입니다 (demo.js:52)
  - awaiting_plan_approval이 그대로 나옵니다. 좁은 Goal 목록에서는 배지가 제목을
    밀어냅니다.
  - → "승인 대기", "진행 중", "리뷰 중", "완료" 같은 한국어 라벨로 매핑합니다.
    색은 지금 그대로 두면 됩니다.

  10. 접근성
  - Goal 목록의 li에 onclick만 있어 Tab이나 Enter로 선택할 수 없습니다.
  - 포커스 스타일이 없습니다.
  - 입력창이 전부 placeholder만 쓰고 label이 없습니다.
  - .muted 색 #6b6b6b의 12px 글씨는 대비가 경계선 수준입니다.

  11. 모바일
  - 900px 이하에서는 1열이 되어 Goal을 눌러도 상세가 화면 아래쪽에 생깁니다.
    아무 반응이 없는 것처럼 보입니다.
  - → 선택할 때 detail.scrollIntoView()를 호출합니다.
  - Task 테이블은 6열이라 가로로 넘칩니다. overflow-x:auto 래퍼가 필요합니다.
  - nav.links에는 flex-wrap이 없습니다.

  추가하면 좋은 것

  - Goal 진행 단계 표시: 생성 → Plan → 승인 → Task 실행 → PR → 머지 중 지금
    어디인지, 누구 차례인지("당신의 승인 대기" / "GitHub에서 머지 대기")를 상세
    상단에 보여 줍니다. HITL 제품의 핵심 메시지인데 지금은 배지 하나뿐입니다.
  - 머지 대기 안내: Task가 in_review일 때 "GitHub에서 PR을 머지하세요 ↗" 버튼을
    둡니다. 지금은 상단 안내문 3번을 기억하고 있어야 합니다.
  - 경과 시간과 생성 시각: Goal 목록과 Plan 생성 중 화면에 "2분 경과"를
    표시합니다. 몇 분씩 기다리는 서비스에서 가장 불안한 구간입니다.
  - Goal 목록 필터: 취소되거나 완료된 Goal을 숨기는 필터입니다. 테스트를
    반복하면 cancelled가 쌓입니다.
  - WS 상태 점(●): 연결이 끊긴 채 30초쯤 지나면 상단에 경고 배너를 띄웁니다.
    지금은 이벤트 섹션 제목 옆의 회색 글씨뿐입니다.
  - 브라우저 알림 또는 탭 제목 변경: Plan이 올라왔을 때입니다. 기다리는 동안
    다른 탭에 가 있는 경우가 많습니다.
  - LLM 선택기 개선: openai — gpt-5.6-luna만 나오는 대신 속도나 비용 힌트를 한
    줄 붙입니다. 라이브 테스트는 늘 openai로 하시는데 /llm 기본값은 아직
    ollama입니다.
  - 다크 모드: CSS 변수가 이미 있어 prefers-color-scheme 블록 하나로 되는데,
    #eef3ff 같은 하드코딩 색 몇 개는 변수로 먼저 빼야 합니다.
  - favicon도 없습니다.

  제거하거나 줄이면 좋은 것

  - 상단 안내문 3단계 박스 (index.html:26-33): 매번 세로 공간을 크게 차지합니다.
    <details>로 접고 첫 방문 때만 펼치거나(localStorage), Goal이 없을 때만 보여
    줍니다.
  - 예시 Goal 버튼 3개: Goal이 이미 여러 개 있으면 방해가 됩니다. "예시 ▾"로
    접습니다.
  - "데모 콘솔" 표기와 demo-note: 지금 demo_mode:false로 운영 중인데 제목은
    "데모 콘솔"입니다. 승인자 계정은 judge로 고정돼 있어 실제 사용자에게는
    혼란을 줍니다.
  - 관리 토큰 입력칸: 연결 폼 안에 숨겨져 있는데 프로젝트 삭제에도 쓰입니다
    (demo.js:225). 데모 모드에서 삭제하려면 접힌 "repo 연결" 폼을 열어 토큰을
    넣어야 하는 구조입니다. 삭제할 때 직접 묻는 편이 낫습니다.
  - Goal 입력의 "영어 한 문장" 제약 문구: 제약이 실제로 있다면 이유를 툴팁으로
    달고, 없다면 지웁니다.

  UX는 아니지만 짚어 둘 것

  과금)과 프로젝트 삭제에 관리 토큰도 필요 없어 보입니다. 쓰기 요청은 직접 보내

  재활성화를 검토해 보세요.
