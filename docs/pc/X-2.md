원칙(사용자, 2026-09-13): 프롬프트를 개별로 손대지 않는다. 튜닝 한 번 = RepoSummary(입력) → Plan → 분해 →

## 결론 (2026-09-13, 로컬 14b 기준 4회)

- **분해는 좋아졌다.** 기존 클래스를 다시 만드는 Task 소멸, T-n 번호와 30분~2시간 크기, 파일이 다르면 병렬, ≥3 Task 코드 검증. (테스트를 별도 Task로 쪼개는 습관은 2/4회 남음.)
- **코딩의 남은 실패는 한 종류다**: 모듈 전역 `store`를 읽는 Flask 라우트를 테스트할 때 그 객체를 import 하지 않고 새 객체를 만든다. 재시도 진단 프롬프트가 한 번은 잡았고(1차 Task 1, 2회차 통과) 나머지는 못 잡았다. 14b는 "정의한 모듈에서 import" 지시를 3회 연속 무시하므로 프롬프트로 더 밀어붙이지 않는다 — 원칙대로 세트 튜닝은 여기서 멈추고, 최종 판정은 D-33대로 Anthropic.
- **입력 쪽 남은 과제**(프롬프트 아님): (1) 워커가 대상 repo 의존성을 설치해야 한다(1차 실패 원인; 지금은 픽스처용 `fixtures` 그룹으로 우회) (2) 모든 라우트가 `main.py` 한 파일에 있어 Task가 전부 직렬 — 첫 Task 실패가 나머지를 막는다. 분해가 "라우트 파일 분리"를 제안하게 하거나(설계 §10.1 owned_paths) Review Agent(MVP 2)가 필요.
- 비용(14b): Goal 1회 = orchestrator ~2.9k/1.3k + Task당 성공 ~2.4k/0.8k, 실패 ~6.7k/1.9k 토큰. 호출당 20~65초.

다음 실행: `.env`에 `HITL_LLM_PROVIDER=anthropic` 후 같은 명령(`--dump` 포함) → 이 표에 행 추가.

## P9.5 — 공개 데모용 로컬 모델 선정 (2026-09-16, 커밋 2ce534a 프롬프트 세트)

사용자 요청: gemma4(12b/26b) 후보. 이 서버 Ollama 0.20.0은 `gemma4:12b` manifest를 거부한다(412 "requires a newer
version of Ollama") — Ollama를 올려야 시도 가능. `gemma4:26b`(19GB)는 12GB VRAM 초과라 제외. 그래서 이미 있는
`gemma4:e4b`(8B, 9.6GB)와 현행 `qwen2.5-coder:14b`를 같은 Goal·같은 조건으로 2회씩 돌렸다
(`scripts/e2e_dry_run.py tests/fixtures/sample_repo "Add a /users CRUD endpoint with tests" --dump`).

| 모델 | 회차 | Task 수 | done | 브랜치 | PR | Plan/분해 1회 통과 | 코딩 토큰(in/out) | 실행 시간 |
|---|---|---|---|---|---|---|---|---|
| qwen2.5-coder:14b | 1 | 4 | 1 | 2 | 1 | ○ | 23.4k / 9.9k (10 calls) | 6분 17초 |
| qwen2.5-coder:14b | 2 | 6 | 0 | 1 | 0 | ○ | 7.1k / 1.8k (4 calls) | 1분 58초 |

| gemma4:e4b | 2 | 6 | 1 | 2 | 1 | ○ | 13.9k / **14.9k** (7 calls) | 5분 13초 |

- 실패 종류는 둘 다 같다(X.2 결론의 한 종류: 첫 Task가 3회 실패하면 `main.py`를 공유하는 나머지가 대기).
- 판정 기준(Plan 1회 통과 ∧ done ≥ 현행 ∧ 호출당 ≤ 60s): 두 모델 모두 Plan 1회 통과, done 최대 1로 **동률**.
  e4b는 출력 토큰이 14b의 2~5배(장황한 편집 응답)라 호출당 시간이 더 길고(41~57s vs 18~50s) VRAM 여유도 비슷하다.
- **결정: 현행 `qwen2.5-coder:14b` 유지** (동률이면 현행). `gemma4:12b`는 Ollama 업그레이드
  (`curl -fsSL https://ollama.com/install.sh | sh`) 뒤 같은 명령으로 2회 돌려 이 표에 추가하고, done이 더 많으면 교체.
- 데모 `.env`: `HITL_LLM_PROVIDER=openai_compat`, `HITL_LLM_MODEL=qwen2.5-coder:14b`, `HITL_SCHEDULER_MAX_WORKERS=2`.
